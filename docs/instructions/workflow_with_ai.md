# Инструкция: рабочий процесс с ИИ и GitHub

## 1. Роли

- **Человек**:
  - задаёт направление,
  - утверждает концепции,
  - принимает финальные решения.

- **ИИ-ассистент**:
  - генерирует текст и код,
  - помогает структурировать документацию,
  - предлагает варианты решений.

## 2. Типовой цикл работы

1. Сформулировать задачу для ИИ:
   - например: «добавить раздел о допущениях в главу Метод».

2. Получить от ИИ:
   - текст Markdown **или**
   - блок PowerShell для автоматического создания/обновления файла.

3. Вставить PowerShell-блок в консоль:
   - выполнить \Set-Content\, \git add\, \git commit\, \git push\.

4. Проверить:
   - \mkdocs build\
   - при необходимости — \mkdocs serve\ и визуально посмотреть сайт.

## 3. Принципы безопасного использования ИИ

- Не позволять ИИ **самостоятельно переписывать аксиомы** проекта.
- Вносить крупные смысловые изменения только после осознанного решения.
- Любое нетипичное поведение (ошибки, странные решения) фиксировать в
  \problems_and_solutions.md\.

## 4. Связь с техническим планом

- При переходе из Фазы к Фазе (см. \	echnical_specification/master_plan.md\)
  желательно:
  - создать/обновить соответствующий раздел в документации,
  - добавить запись в хроники,
  - при необходимости — расширить инструкции.

# Инструкция: правила ведения репозитория SIGADEFA

## 1. Общие принципы

- Репозиторий — это **единое пространство** для:
  - кода (\src/sigadefa\),
  - научной структуры (\docs/\),
  - технического плана (\	echnical_specification/\),
  - хроник (\sigadefa_chronicles/\).

- Всё, что попадает в \main/sigadefa\, должно быть:
  - осмысленным,
  - воспроизводимым,
  - описанным в документации.

## 2. Перед любым коммитом

1. Проверить, что код запускается (минимум — базовые скрипты).
2. Проверить, что сайт собирается:
   - \mkdocs build\
3. Убедиться, что структура не поломана:
   - ссылки в меню не ведут в никуда,
   - нет случайных временных файлов.

## 3. Стиль коммитов

Рекомендуемый формат сообщений:

- \Add ...\ — добавление нового блока (файла/функции/главы).
- \Fix ...\ — исправление ошибки или неточности.
- \Update ...\ — доработка существующего текста/кода.
- \Refactor ...\ — изменение структуры без смены смысла.

Примеры:

- \Add Chapter IV methodology docs\
- \Fix audio_export import path and frequency_model syntax\
- \Update introduction relevance text\

## 4. Научный смысл и аксиомы

- Изменения в базовых концепциях SIGADEFA
  (аксиомы, гипотезы, смысл рун, интервалов) должны:
  - фиксироваться в \	echnical_specification/master_plan.md\,
  - сопровождаться записью в \sigadefa_chronicles\.

- Нельзя «тихо» менять смысл модели без следа.

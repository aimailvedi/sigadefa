# SIGADEFA
## Протокол наполнения репозитория и синхронизации смыслов
*(каноническая инструкция для человека и ИИ)*

---

## 1. Назначение документа

Этот документ определяет:
- как наполняется репозиторий SIGADEFA;
- что должно обновляться после каждого изменения;
- как синхронизируются:
  код, документация, сайт, хроники, философия, артефакты;
- как должен действовать ИИ внутри проекта.

Документ является обязательным к соблюдению.

---

## 2. Золотое правило SIGADEFA

> Любое изменение должно оставить след:
> в коде, в документации, в хрониках и в инженерной памяти.

Если следа нет — изменение считается **несуществующим**.

---

## 3. Типы изменений и обязательные действия

### 3.1. Обновление философии / смысла

Если изменено:
- мировоззрение,
- концепция,
- трактовка языка,
- смысл проекта,

обязательно:

1. Обновить соответствующий файл в:
   docs/concept или docs/foundations
2. Добавить запись в:
   sigadefa_chronicles
3. При необходимости — скорректировать:
   technical_specification/scientific_outline.md
4. Зафиксировать Git-коммитом с философским смыслом.

---

### 3.2. Обновление кода

Если изменён код:

1. Проверить запуск локально.
2. Обновить описание в:
   docs/implementation
3. Если появился новый эффект (звук, визуал):
   - сохранить артефакт,
   - добавить запись в хроники.
4. Зафиксировать Git-коммитом с техническим смыслом.

---

### 3.3. Обновление сайта (MkDocs)

Если изменён сайт:

1. Проверить nav в mkdocs.yml.
2. Проверить, что файл существует.
3. После push:
   проверить сайт GitHub Pages.
4. При смысловых изменениях:
   внести запись в хроники.

---

## 4. Протокол одного рабочего шага

Каждый шаг должен иметь:

1. Техническое действие.
2. Артефакт (файл / звук / изображение).
3. Документационное отражение.
4. Хронику.
5. Git-фиксацию.

---

## 5. Правила именования

- Документы: английский или транслит, snake_case
- Хроники: смысловые имена
- Коммиты: отражают суть, а не просто “update”

---

## 6. Промпт-инструкция для ИИ (каноническая)

ИИ обязан:

1. Не изменять:
   - аксиомы,
   - базовую философию,
   - каноническую структуру,
   без подтверждения человека.

2. Любое предложение ИИ должно:
   - указывать, какие файлы будут изменены;
   - указывать, какая глава затронута;
   - указывать, нужна ли запись в хрониках.

3. ИИ не имеет права:
   - удалять существующие файлы без разрешения;
   - менять структуру разделов без обсуждения;
   - “упрощать” философские тексты.

4. ИИ обязан вести:
   след → фиксация → хроника → публикация.

---

## 7. Контроль целостности проекта

Перед каждым новым этапом проверяется:

- совпадает ли научная структура с сайтом,
- совпадает ли сайт с хрониками,
- совпадает ли код с документацией,
- зафиксированы ли ключевые события.

---

## 8. Статус документа

Документ активный.
Используется как:
- инструкция,
- промпт,
- протокол безопасности проекта.
